## 🪤 Един капан, който изглеждаше като дефект и НЕ Е

Кешът пази ресурсите по **гол** URL (`js/kb.js`), а страницата ги иска с
версия (`js/kb.js?v=176`). При `caches.match(req)` по точен URL това е
кеш-мис — тоест офлайн би счупило всеки версиониран файл.

**Но `sw.js` вече го покрива** и това е документирано на ред 237:

```js
caches.match(req).then(hit => {
  if (hit) return hit;                                   // точно съвпадение
  return fetch(req)
    .then(res => пазиУспешни(req, res))
    .catch(() => caches.match(req, { ignoreSearch: true })); // ← резервът
});
```

`ignoreSearch: true` маха заявката и намира голия URL.

⚠️ **Цената, която трябва да се знае:** майка, която излезе офлайн веднага
след вдигане на версиите, получава СТАРОТО съдържание под новия номер.
По-добре от нищо, и е съзнателен избор — но не е „винаги най-новото".

## Какво НЕ е проверено

- Първо влизане БЕЗ мрежа изобщо (тоест преди кешът да се е напълнил) —
  там няма какво да се сервира и приложението няма да тръгне. Това е по
  устройство и е обявено в самото приложение: „само първия път".
- Поведение при ЧАСТИЧНО пълен кеш (мрежата пада по средата на първото
  зареждане).
- Реален телефон. Тук е браузър на настолна машина с емулирана телефонна
  ширина.
