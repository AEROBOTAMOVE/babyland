# 🎈 Бейби Ленд — помощникът на мама

**Живо: https://aerobotamove.github.io/babyland/**

Офлайн приложение за майки — от бременността до третата година.
Отваря се от браузъра и се инсталира на телефона като приложение.
След първото зареждане работи **изцяло без интернет**.

## Как се инсталира на телефон

1. Отвори линка в браузъра на телефона
2. Меню → „Добави към началния екран"
3. Готово — иконата стои като на всяко приложение

## Обещания към майката

- никакви дози на лекарства — те са разговор с нейния лекар
- нищо, което брои какво НЕ е направила
- нищо, което приема за дадено партньор, пари, помощ или свободно време
- празно поле не е доказателство: „нямам записано" ≠ „няма"

## Пускане на Netlify

Хранилището е готово за Netlify — не се пипа нищо в кода.

1. В Netlify: **Add new site → Import an existing project → GitHub → AEROBOTAMOVE/babyland**
2. Настройките се четат сами от `netlify.toml`. Ако Netlify ги попита:
   - **Build command:** `node build.js`
   - **Publish directory:** `dist`
   - **Branch:** `main`
3. Deploy.

**Защо не се публикува коренът.** Хранилището носи 245 файла в `dev/`
(пазачи, корпуси, сонди) и още в `qa/`. Те са безценни за работата и нямат
какво да правят на живия сайт. `build.js` прави `dist/` само от
приложението — **163 файла, 17.5 МБ** — и при всяко сглобяване сверява, че
всеки път в `index.html` наистина съществува. Пакет със счупен път е бял
екран за майката, а Netlify би го качил без да гъкне; сега сглобяването пада.

**Кешът.** `dist/_headers` казва на Netlify да НЕ кешира `sw.js`. Ако
браузърът задържи стар service worker, майката остава на старата версия
завинаги — кешът на приложението е „кеш-първо по ТОЧЕН URL" и няма кой да я
освежи. По същата причина всяка промяна в `js/` или `css/` иска вдигнат
номер `?v=` в `index.html`; пазачът `dev/versii_izostanali.js` го проверява.

**Проверка преди качване:**

```
node build.js          # сглобява dist/ и сверява пътищата
node dev/pusni_vsichko.js   # 26-те пазача
```

**Път назад.** Махни `[build]` от `netlify.toml` и сложи `publish = "."` —
сайтът пак тръгва, само че с всичко вътре.

## Пускане на Джъмп.бг

Джъмп работи с **LiteSpeed**, не с Apache. Затова `_headers` и `_redirects`
на Netlify там не правят нищо, а директива, която LiteSpeed не разбира, се
прескача **без грешка**. Правилата им са преведени в `.htaccess`, който
`build.js` генерира сам — на ръка не се пипа.

**Сглобяване:**

```
node build.js --dzhamp   # dist-dzhamp/ + babyland-dzhamp.zip, прочетен обратно и сверен
```

**Качване (през cPanel):**

1. cPanel → **SSL/TLS Status** → домейнът да е със зелен катинар (AutoSSL).
   Без https няма офлайн режим и ключалка на дневника.
2. cPanel → **File Manager** → `public_html` — коренът на домейна, **не** подпапка.
   В Settings включи **Show Hidden Files**, за да виждаш `.htaccess`.
3. **Upload** → `babyland-dzhamp.zip` → десен бутон върху него → **Extract** там.
4. Изтрий ZIP-а от `public_html`.
5. От компютъра: `node dev/proveri_hosta.js https://ДОМЕЙН.bg` — трябва **нула червени**.

**Какво пази `.htaccess`:** само https · един адрес (www → без www) ·
`index.html` и „/" без кеш, за да стига новата версия · `sw.js` без кеш ·
седмица за `js/ css/ lib/`, година за `fonts/ icons/` (като при Netlify) ·
`.well-known` без пренасочване, за да се подновява сертификатът.
**Нарочно НЯМА:** „всичко → index.html", HSTS, 301, `Options` — защо, пише в самия файл.

**Компресията не се пуска от `.htaccess`** — на LiteSpeed тя е от сървъра.
Ако `proveri_hosta.js` покаже, че `kb.js` пътува суров (първото отваряне
става ~10 МБ вместо ~2.7 МБ), пиши на поддръжката на Джъмп да включат
gzip/brotli за `application/javascript` и `application/json`.

**⚠️ Данните на майката НЕ пътуват с домейна.** Браузърът пази всичко по
адрес. Майка, ползвала `aerobotamove.github.io`, на новия домейн вижда
празно приложение. Затова **никога пренасочване от github.io** — мостът е
„Резервно копие 💾": сваля файл на стария адрес, качва го на новия.

**Път назад:** разархивирай предишния ZIP — той носи и предишния `.htaccess`.
Преименуване на `.htaccess.izklyuchen` е само за минути: сайтът тръгва, но
„/" губи no-cache, а `http://` и `www` вече не водят към един адрес.
